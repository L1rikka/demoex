**Linux #6**
> [!NOTE]
> NAT - это механизм преобразования адресов, который позволяет подменять приватный адрес сервиса на публичный при обращении во внешнюю сеть т.е интернет.
Посредник (роутер или шлюз компании), принимает пакеты с "серыми" адресами устройства подменяет их на один "белый" публичный IP-адрес при выходе в интернет. Случилось это из-за исчерпаемости IPV4 адресов и безопасности пользователя. NAT позволяет выводить сотню устройств из локальной сети в интернет используя всего один белый IP-адрес. В домашней сети белый адрес выдает провайдер.
> <img width="610" height="299" alt="opera_5Nf7tjLCHx" src="https://github.com/user-attachments/assets/64f76997-9c14-457d-9ec6-7570da1376cc" />
Существуют три типа NAT
```diff
+ Static NAT - один серый IP-адрес строго привязывается к одному белому. Компьютер всегда выходит в интернет под одним внешним адресом. Используется для серверов.
- Dynamic NAT - выделяется пул свободных белых адресов от 1 до 5. Серый IP получает белый адрес из пула по очереди. Пример: 5 белых адресов и 20 компьютеров. Первые 5 смогут выйти в интернет, 6-й компьютер не сможет выйти, пока кто-то не завершит работу из 5. Используется редко из-за неэффективности (нужно много дорогих белых IP-адресов)
+ PAT - Множество серых IP-адресов выходят в интернет через один белый. Они отличаются между собой по номерам портов. Стандарт в домашних роутерах и большинства офисных сетей.
```

**Linux #7**
> [!CAUTION]
> IP-туннелирование - это создание виртуального канала для отправки оригинального пакета IP-адреса внутрь внешнего пакета (запечатанного) из одной сети в другую. Часто используют для соединения двух пересекающихся IP-сетей не имеющих прямого маршрута друг к другу
> 
> Виды туннелирования:
> 
> *Раздельное* - В VPN/туннель направляется только рабочий трафик, а весь остальной интернет идет напрямую через домашнего провайдера. Из плюсов не тормозит интернет и канал не забивается, из минусов личный трафик не защищен
> 
> *Полное туннелирование* - Весь трафик с устройства сначала упаковывается в туннель, летит на офисный/удаленный сервер и выходит в интернет с него. Из плюсов полная анонимность, но создает огромную нагрузку на VPN-сервер и увеличивает задержку пинга
> 
> *IP-in-IP* - Передача IPv4 поверх IPv4. Не умеет передавать IPv6, протоколы маршрутизации. Используется когда нужно быстро и без нагрузки на процессор связать два сервера с постоянными белыми адресами для передачи трафика
> 
> *GPE* - Всеядный туннель GPE/GRE умеет запаковывать внутрь себя вообще любой сетевой протокол. Внутри одного туннеля можно одновременно передавать Ipv4, IPv6, Ethernet-кадры, протоколы динамической маршрутизации (OSPF, RIP, BGP). Широко используется в корпоративных сетях для связи маршрутизаторов, но не шифрует данные сам по себе. Для защиты GPE обычно заворачивают поверх IPsec
> 
> Для настройки локальной т.е корпоративной сети используем протокол GPE для этого включаем модуль ядра **modprobe gre** т.к само ядро Linux не умеет упаковывать данные в формате GRE.
>

>
> Локальный IP-адрес это реальный адрес текущего роутера HQ-RTR смотрящий в интернет/к провайдеру
> 
> Удаленный IP-адрес это реальный адрес второго роутера BR-RTR в интернете/у провайдера, с которым нужно связаться
>
> Виртуальные адреса созданные уже с помощью туннелирования прописываются в **КОНФИГУРАЦИЯ IPv4**. IP-адрес *10.10.10.1/30* это НОВЫЙ виртуальный IP-адрес который мы назначаем самому туннельному интерфейсу tun1 на роутере HQ-RTR. На противоположном роутере BR-RTR в таком же поле будет стоять *10.10.10.2/30*.
